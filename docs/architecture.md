# 架构

## 总体

```
┌──────────────────────────┐        本地 IPC         ┌────────────────────────────┐
│ Rime 前端（小狼毫/鼠须管） │  ◄──────────────────►  │ 常驻进程 wubi86d（第 3 步起） │
│  librime + 本方案 + Lua    │  只做同步、快速的事     │  模型 / 语音 / 扩展插件       │
└──────────────────────────┘                         └────────────────────────────┘
```

**输入法内（Lua）只做同步、毫秒级的事**：查表、过滤、排序、读取常驻进程已经算好的结果。Rime 的 Lua 过滤器在按键路径上同步执行，任何网络或模型调用都会直接卡住打字。

**常驻进程负责一切慢的或需要权限的事**：本地模型推理、录音与语音识别、扩展插件。它不在的时候，输入法照常工作，只是没有这些增强。

## 分层

| 层 | 位置 | 依赖模型 | 内容 |
|---|---|---|---|
| 基础 | `schema/` | 否 | 五笔86、拼音混输、编码提示、用户词频 |
| 记忆与纠错（第 2 步） | `schema/lua/` | 否 | 记录"用拼音打出来的字"作为薄弱字；常见错码映射 |
| 模型增强（第 3 步） | 常驻进程 | 是 | 候选重排、整句联想；异步计算，超时则回退 |
| 语音（第 5 步） | 常驻进程 | 是 | sherpa-onnx + SenseVoice/Paraformer，模型由用户自行下载 |
| 扩展（第 6 步） | 常驻进程插件 | 视插件 | 提示词片段、本地脚本 |

## 常驻进程与输入法之间的接口（草案）

在写第 3 步之前定下来，后面的语音和扩展都复用它，避免为每个能力单独开通道。

- **传输**：本机回环 HTTP，只监听 `127.0.0.1`，端口和随机令牌写在 Rime 用户目录下的 `wubi86d.json`，每次请求都带上令牌。
- **调用方式**：输入法从不阻塞等待。Lua 发出请求后立即返回，结果在下一次按键时读取；超过时限（默认 80ms）就丢弃。
- **统一的能力描述**：每个能力（模型重排、语音、片段……）都是一个 provider，声明自己的
  - `id`、`version`
  - `triggers`：触发方式，例如前缀 `/`、热键、停顿
  - `permissions`：`network`、`filesystem:<路径>`、`exec`，**默认全部关闭**，需要用户显式授权
- **隐私原则**：常驻进程默认不联网；不记录原始按键流，只记录上屏结果的统计（词频、薄弱字），数据只存在本机用户目录。

能执行脚本的扩展本质上就是键盘记录器的攻击面，所以权限声明和默认拒绝不是可选项。
