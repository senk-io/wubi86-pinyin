# 架构

## 总体

```
┌──────────────────────────────────┐
│ Rime 前端（macOS / Windows）        │
│  librime + 本方案 + Lua             │
│  只做同步、毫秒级的事               │
└──────────────────────────────────┘
```

输入法只有这一层：查表、过滤、排序、提示，全部在 librime 和本方案的 Lua 里同步完成。不接入任何大模型，不运行常驻进程，不开端口，不联网。

早期版本（v0.5.0 及以前）曾有一个调用本地大模型的常驻进程 `wubi86d`，用于项目术语补全和续写联想。它要常驻占用几 GB 内存和算力，内存紧张时会和输入法争抢资源，已整体移除。旧版留下的文件由安装和卸载脚本清理。

## 分层

| 层 | 位置 | 内容 |
|---|---|---|
| 基础 | `schema/` | 五笔86、拼音混输、编码提示、用户词频 |
| 记忆与纠错 | `schema/lua/` | `wubi_memory.lua`：记录"用拼音打出来的字"作为薄弱字，五笔打到时提示完整编码；常见错码映射（待做） |
| 拼音语言模型（可选） | librime-octagram | 统计语言模型（n-gram 词表，不是大模型），让长拼音整句更准；由用户选择下载，见 README |

## 附加功能不能拖垮基本输入

去噪、编码提示、忘码记录、顶字都经 `wubi_safe.lua` 调用。出错（代码缺陷、文件损坏、模块缺失）时，只有该功能自己失效并记一次日志，候选照常送出。`tests/run.sh` 会把忘码记录模块换成加载即报错、每次调用都报错的版本，验证基本输入结果不变。

## 隐私原则

- 只记录上屏结果，不记录按键过程；数据只在本机 Rime 用户目录。
- 系统密码框会禁用输入法，密码不会经过这里。
